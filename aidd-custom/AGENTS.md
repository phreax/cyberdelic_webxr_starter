# Custom Agent Instructions

Settings in this file override the root `AGENTS.md`.

## Read order

1. `vision.md` — source of truth (required before any task).
2. This file.
3. `IWSDK.md` — IWSDK-specific rules and traps (generated by `@iwsdk/create`). Treat as binding for anything touching `iwsdk.config.json`, `src/index.ts`, `src/assets.ts`, `src/components.ts`, `src/scene-assets/`, `public/scenes/`, `public/ui/`. Scoped `AGENTS.md` files in `src/` and `public/*/` add detail.
4. `plan.md` → the active epic in `tasks/`.

## Stack override

The generic `/aidd-stack` skill (NextJS + React/Redux + shadcn) does **not** apply.
Use `aidd-custom/skills/cyberdelic-stack/SKILL.md` instead.

Do **not** use these aidd skills in this project: `aidd-stack`, `aidd-react`,
`aidd-autodux`, `aidd-javascript-io-effects` (redux-saga), `aidd-ecs`
(`@adobe/data/ecs`), `aidd-lit`. IWSDK's built-in ECS owns scene state.

Still applicable: `aidd-tdd`, `aidd-javascript`, `aidd-task-creator`,
`aidd-functional-requirements`, `aidd-product-manager`, `aidd-review`, `aidd-fix`,
`aidd-ui` (design principles only), `aidd-error-causes`, `aidd-namespace`,
`aidd-churn`, `aidd-log`, `aidd-please`.

## IWSDK skills

For scene, model, UIKitML, grab/ray, physics and on-device testing work, invoke the
matching `iwsdk-*` project skill (`.claude/skills/`) — start with `iwsdk-dev`.
aidd process (vision check, TDD, task epics, review) still wraps that work.

## Testing

- Unit: Vitest + Riteway (`assert({ given, should, actual, expected })`), colocated `*.test.ts`, run with `npm test`. Config: `vitest.config.ts` (deliberately without the iwsdkDev plugin).
- Pure logic (parameter store, modulation, audio band math, OSC normalization, theme tokens) **must** be TDD'd in Node.
- ECS systems / rendering / XR input: verify with `npm run typecheck`, then IWSDK runtime tools (IWER emulation, `browser_screenshot`, `xr status`). Don't mock Three.js or IWSDK to unit-test systems — extract pure functions instead.
- Before claiming done: `npm run check` (typecheck + tests) and, for runtime changes, `npm run build`.
